# MMEC 页面加载检查与 Gallery 优化

检查日期：2026-10-28。基线：`main` 的 `505a081e6371ce24223bcbe8f5b83db3dc07388a`。
本分支实现 Gallery 优化；其他页面的发现记录为后续工作，尚未批量改动。

## Gallery 已完成的修改

1. 删除该页面的全屏 loading 遮罩，不再等待 `window.load` 后再淡出 1 秒。
2. 新增 `js/gallery.js`，在 DOM 就绪时初始化 Isotope；图片实际加载/失败时合并刷新布局。
3. 绕开旧的 `imagesLoaded()`：现有库会通过 `new Image().src` 主动请求未完成的图片，导致离屏缩略图也被提前下载。Gallery 不再引入这个库；共享 `custom.js` 仅跳过带 `data-gallery-grid` 的容器，其他相册沿用原逻辑。
4. 生成 102 张 500×313 WebP 缩略图和一张 WebP 横幅，保留全部原文件以及点击放大的原图链接。新文件名包含源文件摘要，避免复用旧图片缓存。
5. 所有图片声明实际宽高；前四张卡片的图片立即加载，其余继续原生懒加载。保留现有翻转效果需要的正反两张图片标签，它们使用相同 WebP URL，浏览器复用下载。
6. Gallery 的 JS 从 19 个外部脚本降至 13 个，CSS 从 14 个降至 10 个。移除 Revolution Slider 的四个脚本和两个样式、`shortcode.js`、`counterup.min.js`、`imagesloaded.pkgd.min.js`、重复字体 CSS 和 loading CSS。保留共享主题初始化仍依赖的插件，避免直接删掉插件产生错误。
7. 外部脚本按原依赖顺序使用 `defer`；横幅提前预加载；Gallery 对共享脚本使用新版本查询参数。

## 全站检查范围与限制

扫描了仓库根目录全部 **42 个 HTML 页面**，包含生产页面和历史模板页；逐页检查图片、内联背景、脚本、CSS 及 CSS 引用路径。同时对全部 42 页进行了桌面 Chromium 本地加载检查，结果见 `browser-inventory.json`。

静态清单 `loading-inventory.json` 中的图片大小，是每页声明的唯一 `img src` 与内联背景文件之和，不包括点击后才使用的链接，也不等于首屏流量。CSS 中的 URL 只检查存在性，未将所有潜在背景图算作实际下载。

本地浏览器全站检查阻止并记录第三方请求，避免把外部网络环境混入本地结果。YouTube、Google Fonts、外部图标库是否可达需要在目标客户地区单独测试。其资源大小不包含在本地结果中。

仓库缺失不一定等于线上缺失。例如 `js/module.menus.js` 本地缺失，但抽查线上返回 200。不能根据本地扫描直接删除这些依赖。

### P1：修复实际无效的依赖与初始化错误

- 本地有 14 页出现 `Cannot read properties of undefined (reading 'style')`。既有的 `js/gal.js` 在缺少 `.mySlides` 时仍直接执行 `slides[slideIndex-1].style`；例如 `mgcert.html` 没有该幻灯片结构但仍引入该脚本。应仅在实际需要的页面加载，或增加空集合保护。此次未更改该文件。
- `css/gal.css` 被 21 页引用但仓库缺失；抽查线上也为 **404**。先判断这些页是否需要其样式，再移除无效引用或补回正确文件。
- 两份相同的字体 CSS 被 35 页重复引用。字体定义还指向 25 个仓库中不存在的 WOFF2 文件。抽查线上 `roboto-v30-latin-regular.woff2` 和 `crete-round-v14-latin_latin-ext-italic.woff2` 均为 **404**。应选择实际使用的字体及字重，补齐授权字体文件或使用稳定的系统字体，合并重复定义。
- 六个行业相册的主脚本会动态请求 8 个仓库中缺失的 JS 模块。至少有线上独有文件，先盘点并补入版本管理，再决定是否精简。
- 多个历史模板页有缺失图片。应先确认是否仍有客户链接或搜索流量，再决定修复、重定向或停止公开，不能仅按模板名称删除。

本地 42 页中 30 页出现至少一个资源 HTTP 错误；这包含历史模板及线上独有依赖，不能直接当作生产站 30 页故障。完整路径见浏览器清单。

### P2：把 Gallery 的加载方式逐步用于其他页面

- 还有 34 页保留全屏等待遮罩；应让正文尽早出现，避免与慢图片、外部 iframe 或脚本共同阻挡可见内容。
- 还有 9 页沿用旧的 `imagesLoaded` 相册初始化。替换前检查是否存在下方图片懒加载和特殊高度布局，避免代理请求提前拉取图片。
- 多数正式页面引入 18–20 个外部脚本、14–16 个样式。按页面组件拆分加载；共享主题中仍无条件调用的插件必须同步改成按需初始化，不能只删 `<script>`。
- 图片较多的页面普遍缺少尺寸。声明宽高以预留位置；首屏重要图片保持立即加载，下方图片才懒加载；按移动/桌面显示宽度提供 `srcset`。
- `media.html` 的 YouTube iframe 已使用 lazy，但仍可改为点击播放封面：用户点击后再创建 iframe，减少首访第三方连接。
- `mmecprod.html` 在桌面本地检查出现横向溢出，应另外排查宽表格、列宽或固定尺寸元素；不属于本次 Gallery 改动。

### P2：服务器与客户地区访问测试

对线上 HTML、`style.css`、`custom.js` 抽查确认已经有 **gzip**，不应把“开启 gzip”列为尚未实施的修复。

本次探测响应没有显示 `Cache-Control` 或 `Expires`。建议在服务器确认实际缓存策略，对带内容摘要的静态图片设置长缓存，HTML 和未版本化脚本使用适合更新频率的策略。现有发布脚本保护并排除了 `.htaccess`，单独提交配置文件不会自动生效，需在 Bluehost 端安排并验证。

本环境线上 GET 样本的首字节约 6.3–6.6 秒，但请求经过执行环境的网络代理，不能归因于 Bluehost，也不能代表上海、北美、欧洲或中东客户。应从目标客户地区测量 TTFB、LCP 和缓存命中；如果跨地区延迟确实较高，再评估 CDN、服务器缓存或主机性能。
